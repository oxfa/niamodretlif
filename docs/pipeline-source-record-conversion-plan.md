# Pipeline source record extraction and output conversion

This plan reflects the discussion after `2026-11-28T12:00:00Z` and the current Prepare, Worker, Aggregate, and GitHub Actions implementation. The scope is every record family supported by the six source formats, plus the bounded parsing fixes below. Unsupported vendor syntax continues to produce diagnostics under the source format's rules.

Update each changed producer and its readers together. Use one canonical shape for each handoff, with no compatibility readers, compatibility naming, or added schema version fields.

## 1. Responsibilities and current implementation

- **Prepare** recognizes the source format, parses original records, validates and assigns normalized domain work, and preserves the records and their individual associations.
- **Workers** process domains grouped by registrable domain. They receive effective profiles, manual routing flags, and identity. Their contract contains no source information or output-format policy.
- **Aggregate** validates complete Worker results, joins outcomes to records by normalized input domain, and owns filtered, review, unactionable, and audit output.

The existing Worker manifest already groups input domains by registrable domain and interns the effective profiles. The current Prepare-to-Aggregate record index and filtered outcome lookup use registrable domains. The Worker result is already a compact one-object JSON payload, while its CSV and TXT sidecars participate in handoff validation. Aggregate derives unactionable output and audit from typed outcomes and currently consumes preprojected review rows. Its filtered writer combines eligibility, AdBlock replay, generic hostname formatting, and file I/O. ## 5. SOLID and package boundaries

- **Single responsibility.** Handlers own source grammar. Common validation owns normalized DNS targets and PSL checks. Aggregate owns eligibility and destination policy. Renderers produce lines and the writer handles I/O.
- **Open/closed.** Add a source form through its handler and the relevant output cases. The orchestration, assignment, and storage flow stay independent of format extensions.
- **Liskov substitution.** Every existing handler follows the same contract for invalid syntax, a valid record with targets, a valid record without targets, and ignored lines. The caller uses that contract directly.
- **Interface segregation.** Renderers need the verified syntax facts, eligible targets, and destination. They do not need the parser, PSL service, worker manifest, or filesystem.
- **Dependency inversion.** Aggregate rendering depends on typed record and outcome facts. Prepare's handlers have no dependency on Aggregate, and Worker execution depends on domain work and effective profiles. [Robert C. Martin on SOLID](https://blog.cleancoder.com/uncle-bob/2020/10/18/Solid-Relevance.html)

Use the existing packages, parsed types, and a pure Aggregate function with shared formatters. A single module inside Aggregate is sufficient if its conversion cases warrant a separate file. The current callers use these contracts within one pipeline release, so there is no independent reuse or release boundary to create (**REP**). Keep grammar and extraction together, and keep each handoff type, codec, and invariant with its contract (**CCP**). Keep contracts narrow so consumers depend on the part they use (**CRP**). Keep dependencies acyclic and directed toward the small, stable record and outcome contracts. Place policy-specific behavior with the owning handlers or renderers (**ADP**, **SDP**, **SAP**).
